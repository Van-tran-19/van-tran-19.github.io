# Database Management System DBSYS

Whether you are checking your bank balance or liking a post on social media, you are relying on databases, the invisible backbone of the modern digital world.

## What is a Database?

A database is a large, integrated collection of data. It models a real world enterprise like students at school for example. 

**What is DBMS (database management system)?** 

To manage this huge collection of data, DBMS is a piece of software designed to store and manage databases. It provides for user the capacity to handle and link data among them. 

**What is a Data Model?** 

A data model is a tool for describing data. The relational model of data, typically a table with rows and columns is the the most widely used way to store data with relation between them. This concept is called a relation. Every relation has a schema, which is a description of a particular collection, using a given data model. A schema describes columns and fields.  

A database contains different level of abstraction from the **physical** level which describes the files and indexes used, the **conceptual** schema which defines logical structure and **views which describe how users see the data.**

> 

**What are the key challenges in DBMS?** 

1. The scan can be very slow due to very large table. 
2. Memory is limited. This introduce the needed to choose the right architecture depending on data. 
3. Security can happen among users, roles and accesses.

> | Query Optimization and execution | Parses, analyzes, and translates a declarative SQL query into an efficient physical execution plan | Evaluates different query plans (join orderings, index usage) using cost estimation (I/O, CPU) and selects the least expensive plan to execute |
> | --- | --- | --- |
> | Relational operators  | Implements the core relational algebra operations required by the query plan. | Executes algorithms for operators like Selection ($\sigma$), Projection ($\pi$), Joins ($\Join$ — nested loop, hash join, sort-merge), Grouping, and Sorting. It requests records from the layer below one record or page at a time (often using an iterator/volcano model). |
> | Files and access methods | Organizes data logically into collections of records (tables) and provides indexing structures. | Manages unordered files (heap files), sorted files, and index structures (such as $\text{B}^+$-trees or Hash indexes). It handles operations like inserting, deleting, and searching for records by search key or Record ID (RID) |
> | Buffer Management | Manages the transfer of database pages between volatile main memory (RAM) and non-volatile storage (disk) | Maintains a pool of memory frames (buffer pool). When a higher layer requests a page, the buffer manager checks if it is already in RAM; if not, it fetches it from disk. It manages replacement policies (e.g., LRU, Clock) and page pinning/dirty flags. |
> | Disk space management | The lowest software layer before the physical database storage. | Interacts directly with the OS/hardware to allocate, deallocate, read, and write raw disk blocks/pages to and from persistent storage (`DB`). It abstracts physical track/sector mapping into a continuous sequence of numbered pages. |
