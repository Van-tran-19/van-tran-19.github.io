### What are NaN values ?

**NaN** means **“Not a Number”**, and in data analysis / machine learning it represents **missing**, **undefined**, or **unrepresentable** values.

In pandas, missing values in DataFrames are stored as `NaN`:

### **Why NaN matters in ML?**

Models **cannot train** with NaN values. You must handle them before training:

- **drop** rows/columns
- **fill** with mean/median/mode
- **use imputation models**
- **encode missingness** as a feature

## **Train/Validation/Test Split**

We will split the dataset in three parts:

- a **training set** (60% of the data), used to fit the models;
- a **validation set** (20%), used to compare models and to choose their settings (for example the number of neighbours `k` of k‑NN in Section 10);
- a **test set** (20%)

The test set must not be used to make any choice. Otherwise, the final estimate would be optimistic.

#### **Why the test set must not be used to make any choice?**

Suppose you try 20 different models and evaluate each on the test set.
You pick the one with the best test score. But that model might be good only on that test set, not in general. You didn’t measure generalization, you measured how well your model fits the test set. This is overfitting to the test set.

We first separate the test set, then split the remaining data into training and validation sets. 


## **Linear Regression without Normalization**

In a first attempt to train a model to predict `mpg`, we will use LinearRegression (from scikit-learn) to train a model using the raw features. Then, we will use it to predict the labels of the validation data.

`LinearRegression` computes the least squares solution directly. No iterative optimization is involved.

```python
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score, mean_squared_error

lin_raw = LinearRegression().fit(X_train, y_train) #We fit a model passing the training features and labels
y_pred_raw = lin_raw.predict(X_val) #We predict on the validation set
```

We will use the mean squared error (MSE) and the $R^2$ score to assess the performance of our model. Write $y_i$ for the true values, $\hat{y}_i$ for the predictions and $\bar{y}$ for the mean of the true values.

- **Mean squared error:** $\text{MSE} = \frac{1}{n}\sum_i (y_i - \hat{y}_i)^2$. It is the average squared error, expressed in squared units of the target (here mpg²). The lower, the better. However, its value alone is hard to judge: is an MSE of 10 good or bad?
- **Coefficient of determination:** $R^2 = 1 - \dfrac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - \bar{y})^2}$. It compares the error of the model with the error of the simplest possible model, one that always predicts the mean $\bar{y}$.
- $R^2 = 1$: perfect predictions.
- $R^2 = 0$: the model does no better than always predicting the mean.
- $R^2 < 0$: the model does worse than always predicting the mean.

$R^2$ has no units. For instance, $R^2 = 0.8$ means that the model removes 80% of the squared error made by always predicting the mean.

```python
r2_raw = r2_score(y_val, y_pred_raw)
mse_raw = mean_squared_error(y_val, y_pred_raw)

print(f"Raw features -> R²: {r2_raw:.3f} | MSE: {mse_raw:.3g}")

#Output: 
Raw features -> R²: 0.817 | MSE: 11.9
```

**What can wee say about this model?** 

This model predicts pretty well on this dataset. We have to compare now with other models to say more about this one.

## **Linear Regression with Normalization**

Now, we will train a new linear regression model after normalizing the input features. In this case, we will standardize features by removing the mean and scaling to unit variance.

**What does “removing the mean and scaling to unit variance” mean?**

It means we transform **every feature** so that:

- its average becomes 0
- its spread becomes 1

This transformation is called standardization. 

**Why do we do this?**

Because raw features have very different scales. Linear regression works better when all features are on the same scale. Standardization fixes that.

This is, for a given feature $x$:

$z=(x−μ)/σ$

where μ is the mean of the training samples and σ is the standard deviation of the training samples.

```python
mu = X_train.mean(axis=0)
sigma = X_train.std(axis=0)
X_train_scaled = (X_train - mu) / sigma
X_val_scaled = (X_val - mu) / sigma
lin_scaled = LinearRegression().fit(X_train_scaled, y_train)
y_pred_scaled = lin_scaled.predict(X_val_scaled)

r2_scaled = r2_score(y_val, y_pred_scaled)
mse_scaled = mean_squared_error(y_val, y_pred_scaled)

print(f"Raw features    -> R²: {r2_raw:.3f} | MSE: {mse_raw:.3g}")
print(f"Scaled features -> R²: {r2_scaled:.3f} | MSE: {mse_scaled:.3g}")
print("W (scaled): ", [f"{w:.3g}" for w in lin_scaled.coef_])
print("W0 (scaled):", f"{lin_scaled.intercept_:.4g}")

#Output
Raw features    -> R²: 0.817 | MSE: 11.9
Scaled features -> R²: 0.817 | MSE: 11.9
W (scaled):  ['-0.361', '-0.67', '0.412', '-5.18', '0.0794', '2.66']
W0 (scaled): 23.51
```

$R^2$ values still the same, MSE too, the features values are much more spread, which is completely normal. The values are just scaled but information still the same, it’s the reason why $R^2$ and MSE still the same.

- If σ is small, the values are close together.

- coefficients become **directly comparable**
- the magnitude of the coefficient = **true importance**

## **Normal Equations and Conditioning**

Linear regression solves:

$(X^⊤X)w=X^⊤y$

where:

- $X$ is design matrix (with a column of ones for the intercept)
- $w$ is the vector of regression coefficients

To compute $w$, you must solve a linear system with matrix $X^⊤X$.

**What is the condition number?** 

The condition number κ of a matrix measures how sensitive the solution of a linear system is to small errors, such as noise in the data or rounding errors in the computer.

- κ ≥1
- κ=1 is the ideal case.
- Roughly, relative errors can be amplified up to κ times in the solution $w$. If , κ≈10m you can lose about  $m$ significant digits of $w$
- A computer working in double precision (the default in NumPy) keeps about 16 significant digits.
- κ is large when the matrix is close to being non invertible, for example when its columns have very different scales or when some columns are nearly redundant.
- for a symmetric matrix such as $X^⊤X$,  $κ$ is the ratio of its largest to its smallest eigenvalue. In particular, for a **diagonal** matrix,  $κ$ is the ratio of its largest to its smallest diagonal entry.

Let us compute κ of $X^⊤X$ for the raw and the standardized training features, together with the correlation matrix of the features.

```python
def with_intercept(X):
    return np.c_[np.ones(len(X)), X]   # adds the column of ones for the intercept

A_raw = with_intercept(X_train)
A_scaled = with_intercept(X_train_scaled)

print(f"Condition number of XᵀX, raw features:    {np.linalg.cond(A_raw.T @ A_raw):.1e}")
print(f"Condition number of XᵀX, scaled features: {np.linalg.cond(A_scaled.T @ A_scaled):.3g}")

corr = pd.DataFrame(X_train, columns=numeric_cols).corr()
display(corr.style.format("{:.2f}"))

#Output
Condition number of XᵀX, raw features:    7.7e+09
Condition number of XᵀX, scaled features: 116
```

**In which case is the condition number larger? Which features are strongly correlated with each other?**

- In the raw dataset, features have **very different scales**
- Some features are **highly correlated**
- This makes $X^⊤X$ close to singular → **ill‑conditioned** → huge κ

After standardization:

- all features have **mean = 0** and **std = 1**
- the columns of $X$ have similar scale
- κ becomes **much smaller**
- the linear system becomes **numerically stable**

Raw features → large κ → unstable 

Scaled features → small κ → stable regression

### Dropping categorical, ordinal encoding and one-hot encoding

These are 3 different encodings. 

**What is feature encoding?** 

Feature encoding is simply the process of turning non‑numeric data into numbers so that a machine‑learning model can use it.

Now, we will compare, on the validation set:

1. **No categorical** (numeric only)
2. **Naïve ordinal encoding**: map categories to integers, in alphabetical order.
3. **Naïve ordinal encoding, another order**: the same idea, with the integers assigned in a different order (`usa` in the middle).
4. **Proper One-Hot Encoding**: one binary column per category. We use `europe` as the reference category (`drop_first=True`): the model gets one column for `japan` and one for `usa`, and their coefficients measure the difference with a European car having the same other features.

```python
categories = sorted(train_df["origin"].unique())   # alphabetical order
mapping = {cat: i for i, cat in enumerate(categories)}

def fit_and_validate(Xtr, Xval):
    model = LinearRegression().fit(Xtr, y_train)
    pred = model.predict(Xval)
    return model, r2_score(y_val, pred), mean_squared_error(y_val, pred)

# Case 1: Drop categorical
lin_drop, r2_drop, mse_drop = fit_and_validate(train_df[numeric_cols], val_df[numeric_cols])

# Case 2: Ordinal/label encoding
def ordinal(d):
    return d[numeric_cols].assign(origin_ord=d["origin"].map(mapping))
lin_ord, r2_ord, mse_ord = fit_and_validate(ordinal(train_df), ordinal(val_df))

# Case 2b: Ordinal encoding with another order
mapping_b = {"europe": 0, "usa": 1, "japan": 2}
def ordinal_b(d):
    return d[numeric_cols].assign(origin_ord=d["origin"].map(mapping_b))
lin_ord_b, r2_ord_b, mse_ord_b = fit_and_validate(ordinal_b(train_df), ordinal_b(val_df))

# Case 3: One-Hot Encoding (reference category: europe)
def one_hot(d):
    dummies = pd.get_dummies(pd.Categorical(d["origin"], categories=categories), drop_first=True, dtype=float)
    dummies.index = d.index
    return pd.concat([d[numeric_cols], dummies.add_prefix("origin_")], axis=1)
lin_ohe, r2_ohe, mse_ohe = fit_and_validate(one_hot(train_df), one_hot(val_df))

# Values given to each origin by the two ordinal encodings
display(pd.DataFrame({"Ordinal (alphabetical)": mapping, "Ordinal (usa in the middle)": mapping_b})
        .loc[categories].style.set_caption("Value given to each origin by the two ordinal encodings"))

# Summary
```

### **Drop the feature**

You remove the categorical feature entirely.
No encoding → no information from that feature.

### **Ordinal encoding**

You assign **one integer per category**:

Alphabetical:

- europe → 0
- japan → 1
- usa → 2

USA‑middle:

- europe → 0
- usa → 1
- japan → 2

This creates a **fake numerical order**.
Linear regression interprets:

usa>japan>europe

even though this ordering has **no real meaning**.

This is why your two ordinal encodings give different R² and MSE:
the model is reacting to the *arbitrary numeric order* you imposed.

### **One‑Hot Encoding (OHE)**

You create **one binary column per category**:

| origin_europe | origin_japan | origin_usa |
| --- | --- | --- |
| 1 | 0 | 0 |
| 0 | 1 | 0 |
| 0 | 0 | 1 |

This encoding does not impose any order. It treats categories as independent, which is correct for nominal data. This is why OHE usually performs better and more consistently.

**How were the different categories mapped in the ordinal mapping? Does this order have a meaning?**

The order has no meaning. Ordinal encoding creates an artificial numerical order between categories that do not have a natural ranking. 

For example:

- europe = 0
- japan = 1
- usa = 2

This implies:

- usa > japan > europe
- the “distance” between japan and europe is 1
- the “distance” between usa and japan is also 1

But these distances are fake.
There is no real numerical relationship between continents.

This is why ordinal encoding is not appropriate for nominal categories.

**Which model performs best? One-hot encoding is the recommended practice for categorical values. Based on your observations, in particular on the two ordinal models and on the share of cars by origin, try to explain the behaviour of the models.**

Surprisingly, the alphabetical ordinal encoding gives the best validation performance.

## **k Nearest Neighbours, written with an AI assistant**

We now turn to a second model seen in class, k nearest neighbours (k‑NN) for regression. To predict the `mpg` of a car, k‑NN finds the `k` cars of the training set that are **closest** to it, and returns the average of their `mpg`. "Closest" is measured with the Euclidean distance between feature vectors:

$\text{dist}(x, x') = \left( \sum_{j} |x_j - x_j'|^2 \right)^{1/2}$

where the sum runs over the six numeric features (cylinders, displacement, horsepower, weight, acceleration, model_year).

We use only the six numeric features: `origin` is dropped again.

Unlike linear regression, k‑NN has a setting that we must choose ourselves: the number of neighbours `k`. We will choose it using the **validation set**.

```python
import pandas as pd
from sklearn.neighbors import KNeighborsRegressor
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import r2_score
import matplotlib.pyplot as plt

# Values of k to test
k_values = [1, 3, 5, 10, 20]

# Standardize features using ONLY the training set
scaler = StandardScaler()
X_train_std = scaler.fit_transform(X_train)
X_val_std = scaler.transform(X_val)

# Store results
results = {
    "R2_raw": [],
    "R2_std": []
}

for k in k_values:
    # --- Raw features ---
    knn_raw = KNeighborsRegressor(n_neighbors=k)
    knn_raw.fit(X_train, y_train)
    y_pred_raw = knn_raw.predict(X_val)
    r2_raw = r2_score(y_val, y_pred_raw)

    # --- Standardized features ---
    knn_std = KNeighborsRegressor(n_neighbors=k)
    knn_std.fit(X_train_std, y_train)
    y_pred_std = knn_std.predict(X_val_std)
    r2_std = r2_score(y_val, y_pred_std)

    # Store
    results["R2_raw"].append(r2_raw)
    results["R2_std"].append(r2_std)

# Create DataFrame with correct index and columns
knn_results = pd.DataFrame(results, index=k_values)

# Plot
plt.figure(figsize=(8,5))
plt.plot(k_values, knn_results["R2_raw"], marker='o', label="Raw features")
plt.plot(k_values, knn_results["R2_std"], marker='o', label="Standardized features")
plt.xlabel("k (number of neighbors)")
plt.ylabel("Validation R²")
plt.title("KNN Validation Performance vs k")
plt.legend()
plt.grid(True)
plt.show()
```
