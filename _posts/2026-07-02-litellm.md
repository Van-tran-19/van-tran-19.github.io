## What is LiteLLM? [1]

LiteLLM is an open-source AI gateway that gives a single unified interface to call 100+ LLM providers (OpenAI, Anthropic, Gemini…). It is used as a Python SDK for direct library integration, or it deploys an AI gateway (Proxy server) as a centralized service (one place where all traffic goes).

### What is Python SDK?

A Software Development Kit (SDK) is a package of tools, code, and documentation that can be used without dealing with low-level details.
Common Python SDKs include the OpenAI Python SDK, Google Cloud SDK, etc.

A Python SDK typically contains pre-built Python classes and functions so it isn’t necessary to manually call raw HTTP endpoints. In fact, without an SDK, a user must interact with a service using manual HTTP requests (build the URL, add headers, manage authentication, serialize JSON, send the request, parse the response, handle errors, retry on failure, manage rate limits, etc.).

example without SDK: 

```python
import requests

url = "https://api.example.com/v1/generate"
headers = {"Authorization": "Bearer XYZ", "Content-Type": "application/json"}
payload = {"prompt": "Hello world"}

response = requests.post(url, json=payload, headers=headers)
data = response.json()
print(data["output"])
```

example with SDK:

```python
client = ExampleClient(api_key="XYZ")
result = client.generate("Hello world")
print(result)
```

It also includes authentication helpers like API keys, tokens, OAuth, documentation, examples, and tools.

### What is a proxy server? [2]

An AI gateway acts exactly as a proxy server. The user app never talks directly to the LLM provider. Instead, the app talks to the AI gateway, which forwards the request, receives the response, and sends it back to the user app.

App $\rightarrow$ AI gateway $\rightarrow$ LLM provider

A proxy is a sort of machine that sits between the local host and the internet. It receives a request, forwards it, gets the response, and sends it back to the local host. Why do proxies exist? Proxies hide the local host's IP address from the internet, giving privacy each time the local host browses the internet. It controls and filters traffic, it contains a content cache where it can store frequently accessed pages to make them load faster, and it bypasses restrictions. There are different versions:

- forward proxy
- reverse proxy
- transparent proxy
- socks proxy

### **What an AI Gateway provides?**

An AI gateway is a single entry point that all apps use to access AI models. All apps call one internal endpoint, regardless of the provider. This removes the need for each team to integrate dozens of SDKs. Every provider has different request/response formats. The gateway normalizes everything, which drastically simplifies development. It also enforces security, preventing the leaking of provider API keys to developers or client apps. The gateway can also track costs per model, per team, etc., which is essential for companies spending thousands per month on LLMs. It contains an intelligent routing service which can choose the best model depending on what is needed, and it also ensures high availability.

### What are MCPs?

The Model Context Protocol is a protocol that lets AI models use tools, access data, and interact with external systems. Before MCP, every agent framework had its own tools. MCP solves this by providing one universal protocol. It is a way to let an LLM interact with tools, APIs, files, databases, or local resources in a standardized way.

### How use it?

Three components are important to understand MCP:

1. **The MCP server:** The part exposing tools to the models. Each tool is described in a JSON schema. The server runs locally or remotely and communicates with the model.
2. **The MCP client:** Usually the LLM runtime (VS Code AI, agent framework). The client discovers available tools and receives results.
3. **The protocol:** Powered by JSON-RPC.

## Why LiteLLM?

The LLM landscape is highly fragmented. You might want to use an OpenAI model for one task, Gemini for another, and a Hugging Face model for production. Every single one of these providers has its own SDK, its own API format, and its own way of handling errors, streaming, and tool calling. LiteLLM lets you treat any LLM provider as if it were OpenAI.

It takes the OpenAI format and maps it to over 100+ other LLMs. Instead of rewriting the entire code, you just have to change the model line.

 

```python
import litellm

# Call OpenAI GPT-4o
response1 = litellm.completion(
    model="openai/gpt-4o",
    messages=[{"role": "user", "content": "Hello World!"}]
)

# Call Anthropic Claude 3.5 Sonnet (using the exact same syntax)
response2 = litellm.completion(
    model="anthropic/claude-3-5-sonnet-20240620",
    messages=[{"role": "user", "content": "Hello World!"}]
)
```

LiteLLM standardizes what comes back (streaming tokens, function/tool calling). It lets you define a list of back-up models so if one hits a rate limit or goes down, for example, LiteLLM can route the request back without dropping the user’s request.

## Multi‑LLM Routing

The LiteLLM router is its most powerful feature. It allows users to group multiple endpoints under a single model name alias and dynamically route traffic between them based on performance, availability, cost, or prompt complexity.
