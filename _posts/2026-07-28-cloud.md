# Cloud

In a company like Worldline, Cloud is used everywhere to store applications, data, services. Worldline provides GI, Google: GCP, Amazon: AWS. They constitute the future of software environment.  

## What is the Cloud?

Cloud computing is a way of using IT. It provides customers to get computing resources over the internet from anywhere. Resources are on-demand, the provider allocates them to users and they are also flexible, which means that users can add and remove as they want. 

Customers pay only what they use or reserve what they will use. 

#### Why is the cloud model compelling nowadays?

Cloud model was transforming into virtual space and nowadays into container-based architecture. User can rent this space instead of investing in data center real estate. 

Cloud computing has evolved to giving place for infrastructure management and services management. 

It provides two new types of offering: 

- **IaaS** which is infrastructure as a service. It offers raw compute (it’s the direct processing power of hardware: CPUs, GPUs …), storage and network capabilities.
- **Paas** which is platform as a service. It offerings bind code to libraries that provide access to the infrastructure application needs. In fact, when user writes an app, user deals with a database, a file storage system, networking, authentication, logging etc.. In PaaS, the cloud provider gives you ready-made libraries, SDKs, and APIs that automatically connect your code to these services.

Cloud is the current place where SaaS (software as a service) are located. SaaS provides the entire application stack, delivering an entire cloud based application that customer can access and use. 

### Cloud network

Cloud networking is the set of **networking concepts, tools, and architectures** that allow cloud resources to communicate securely and efficiently.

It is built to give the highest possible throughput with lowest possible latencies, by leveraging more than 100 caching nodes worldwide. The principle is that high demand content is cached for quicker access. Cloud infrastructures are located all around the world and are divided into sub-regions to facilitate provided services and access management and where services are deployed.  

### Security

Security goes to physical security of data-centers into security of hardware and software of applications. 

At the hardware level, security is divided into 3 different features. 

- The first is **hardware design and provenance**, which refers to how the physical hardware is built, sourced, verified, and managed inside cloud data centers.
- The next feature is a **secure boot stack**, which is a chain of security mechanisms that ensures a machine (physical or virtual) boots using trusted, verified, untampered software.
- The last feature are premises security. It refers to all the physical and environmental protections applied to data centers, server rooms, and hardware facilities where cloud infrastructure physically exists.

Next, at the service deployment layer, where the key feature is the encryption of inter-service communication. It ensures that all traffic between cloud services is secured, authenticated, and protected. It is implemented using: TLS (transport layer protocol: encrypts data in transit), mTLS (extension of TLS by requiring both client and server to present certificates), service mesh encryption, private networking with encryption and it protects model inference, embeddings, internal APIs, databases, microservices. 

Then, they have the user identity layer. This layer protects both human users and machine identities by using authentication (AuthN), authorization (AuthZ) and identity governance (IdP) services. It ensures and manages: who the user is? how the user proves their identity? what the user is allowed to do? how access is controlled and monitored? 

The next security layer is the storage services layer. Cloud providers encrypt data before it is written to disk, using centrally managed keys at the storage service layer. The process follows this steps: data is sent to a storage service, which encrypts the data in memory using strong algorithms such as AES-256, so only the encrypted version is written to disk. The encryption key is managed by a key management service (KMS). 

Cloud services are exposed in internet through front-ent like GFE for google. The front-end ensures TLS termination using CA-issued certificates (Certificate Authority is a trusted organization that verifies identities on the internet) and public/private key pairs, it also ensures perfect forward secrecy and DoS protection (It refers to all the techniques used to prevent, detect, and mitigate attacks that try to overwhelm a system’s resources so legitimate users can’t access it). 

Finally the last security layer is the operational security layer. It protects by using intrusion detection, insider risk reduction (Strict limitation and monitoring of employees with administrative access), employees U2F security keys and secure software development practises. 

### Open Source ecosystem

Some organizations fear that moving to the cloud will trap them with one provider. Google addresses this by ensuring customers can run their applications elsewhere if they ever choose to leave. 

Open source technologies like TensorFlow is used across many platforms. Cloud providers generally design tools working across multiple platforms by using for example kubernetes that let customers deploy across different cloud providers.

### Cloud resource hierarchy

Cloud architecture is composed by 4 different layers. 

At the top level, organisation node is contained the entire company/domain which is provided central administrative control. Policies and permissions defined at higher levels (Organization or Folder) automatically inherit downward to all child projects and resources inside them. 

Next, folders are used to group projects or other subfolders. It allow teams to delegate administrative control independently and avoid duplicate permission management.

At the second level, projects are the fundamental unit for enabling APIs, managing billing, adding collaborators and using services. 

At the first level, they have the resources level, which contains the individual cloud components used by user like VMs (virtual machine), BigQuery tables..

### Identity and access management (IAM)

IAM allows administrators to control who (principals) can do what (roles) on which resources. They exist 3 types of IAM roles. 

The basic role is the first one. It is used for small teams requiring quick setups. Roles are owner, viewer, editor and billing administrator. 

Then, they have predifined roles which enforce the principle of least privilege when predifined roles are to broad. It is used for most standards production workflow. 

Finally, they have custom roles. For example, let users to start/stop a service without allowing them to modify configurations. 

### Service accounts

Service accounts allow app running on a VM to interact with other cloud services without human intervention. They are identified by an email address and use cryptographic keys to authenticate. IAM role associated to the services account determines what the VMs app can do. 

They act as both a resource and an identity. 

As an identity, they can be granted role to perform actions on other cloud services. 

As a resource, they can have IAM policies applied directly to them. This allows administrators to control which human users or services can manage or act as the service account itself.

### How to access and to interact with Google cloud (GCP)?

GUI (google user interface) is designed to manage cloud resources visually through browser. 

User can have access to the cloud via the shell by installing google cloud SDK, via APIs (like API explorer, an interactive tool inside the console to test available APIs and their versions) and client libraries with pre-built code packages provided by Google in popular programming languages (Java, Python, Node.js, C#, Go, PHP, Ruby, C++). 

Finally, you can have access to GCP via the mobile app. 

## Virtual machines and Networks in the cloud

### Virtual private cloud networking (VPC networking)

VPC tends for virtual private cloud, it is created within Google Cloud’s public cloud infrastructure for combining both the scalability of a public cloud with the security and data isolation of a private cloud. It works by controlling network traffic using firewall rules, segmenting networks and routing traffic with custom static routes. 

One of its key feature is that Google Cloud VPC networks are global. Virtual machines located in different regions (for example, one VM in North America and another in Asia) can communicate privately over Google's internal global fiber backbone using internal IP addresses without traffic needing to traverse the public internet or pass through complex VPN tunnels. 

### Compute Engine

It is a google cloud infrastructure as a service (IAAS) platform that allows user to create and run VMs with full operating system controls where user can customize the CPU power, memory size, storage types and the choice of OS (Linux, MacOS etc..). It includes a cloud marketplace and a tool management section. 

To propose this, compute engine has a feature called autoscalling allowing compute engine to automatically add or remove VM instances in real time based on incoming traffic or resource utilization metrics. 

### Cloud load balancing

It runs on Google's infrastructure (not inside VMs), meaning it automatically scales to handle any traffic volume without manual intervention and it can instantly absorb massive, unexpected spikes in demand without needing to notify Google Cloud Support in advance. It handles HTTP/HTTPS, TCP, SSL, and UDP traffic.

Google Cloud classifies its load balancers by their operational layer in the OSI model:

```markdown
                    [ Incoming User Traffic ]
                                 |
        +------------------------+------------------------+
        |                                                 |
[ Layer 7: Application ]                         [ Layer 4: Network ]
        |                                                 |
  • HTTP / HTTPS Traffic                            • TCP / UDP / IP Protocols
  • Content-based routing                           • Two subtypes:
  • SSL/TLS Termination                             ├── Proxy (Terminates connection)
  • External & Internal                             └── Passthrough (Preserves source IP)
```

### Cloud DNS and cloud CDN

A cloud DNS (domain name system) translates human-readable domain names into IP addresses so users can find applications hosted on the cloud. A cloud CDN (context delivery network) accelerates content delivery by caching static and dynamic web content on global network of edge caches (servers located physically closer to end users). It lets much faster load times for users. 

### Connecting networks to google VPC

They exist 3 options to provide a way to bridge information between the cloud service provider and the customer, depending on the budget and the needs. 

The first option is the **Cloud VPN**. It works by establishing encrypted IPsec VPN tunnels over the public internet between peer network and Virtual Private Cloud (VPC). To route data, cloud routers are used by working alongside Cloud VPN to exchange dynamic routes automatically using Border Gateway Protocol (BGP). Adding new subnets to VPC automatically updates on-premises routing tables. It is the best for organizations needing cost-effective, private-to-private (RFC 1918) IP connectivity where standard internet bandwidth and performance are sufficient.

**Peering options** are presented as the second option. Peering is the direct connection to edge network using public IP addressing. If companies are already colocated in a PoP or willing to install and manage their own routing equipment in PoP, the best option is to connect routing hardware directly to a point of presence (PoP) on a public datacenter: **Direct Peering;** but if the companies don’t need private IP access and want public reachability without installing physical hardware in a PoP, then the best option is to connect to public IP services via a partner service provider’s network: **Carrier Peering**.   

**Interconnect** are the third option. Interconnect options bypass the public internet completely. **Dedicated internet** is a option that is used for organizations requiring high bandwidth, low latency and private circuits with hardware in a colocation facility. It works by using a direct physical connection between private network and cloud network. Otherwise, if user cannot physically colocate equipment in a PoP or need lower bandwitdh options, then the best option is using a **Partner interconnect**. It works by using a private connectivity established through a supported third-party service provider. Finally, if the user needs a multicloud strategies with low complexity, high bandwidth and a site-to-site tranfer between cloud environments, then **cross-cloud interconnect** is the best options because it uses a dedicated high-bandwidth physical link provisioned by the Cloud provider to directly peer your VPC with another cloud provider.

## Storage in the Cloud

****The cloud provides five core storage and database options, each designed for specific data types and workload demands: Cloud Storage, Cloud SQL, Cloud Spanner, Firestore  and Cloud Bigtable.

### Cloud storage

Cloud storage is a storage architecture that stores data as packaged objects (objects are stored using binary data, metadata and a globally unique URL key) rather than standard file storage. This storage is ideal for BLOBs (unstructured binary large objects) like videos, images, audios, etc…

Objects are stored in globally named containers called **buckets**, which are assigned a specific geographic location to minimize latency for end users. Objects cannot be directly edited, any modification creates a new version.

Cloud storage offers four primary storage depending to data access frequency. The **standard** access manages hot data which are frequently accessed. Then, the **nearline** storage, coldline storage, archive storage manages respectively data that has been used once per 30 days, per 90 days and per year. 

All storage classes offer unlimited scale, low latency, worldwide access, high durability, geo-redundancy (if multi-region/dual-region), and uniform APIs/tools. Autoclass is also a specific feature that automatically transitions objects to colder storage classes if unaccessed to reduce costs, and restores them to Standard storage when accessed.

### Cloud SQL

Cloud SQL provides managed relational databases supporting MySQL, PostgreSQL, and SQL Server without requiring manual software installation or maintenance. It ensures encryption by default and firewall protection. 

### Spanner

It’s a database service combining the scaling benefits of NoSQL with the structured power and ACID (which stands for Atomicity, Consistency, Isolation, Durability, the four fundamental guarantees that ensure database transactions remain reliable even in the presence of errors, crashes, or concurrent access) guarantees of standard relational databases.

### Firestore

Firestore has a flexible NoSQL structure where data is stored as documents of key value pairs. Documents are grouped into collections. It’s particularly efficient to update connected web, mobile or server clients in real time when data changes. It provides automatic multi-region replication, strong consistency guarantees, atomic batch operations, and full ACID transaction support.

### BigTable

Bigtable is a fully managed, wide-column NoSQL database service built for massive scale, low latency, and high throughput. It currently powers major Google services including Search, Analytics, Maps, and Gmail. Use bigtable if the workload is requiring large volume, high throughput, NoSQL and big data/ML.

## Containers in the Cloud

### Introduction to containers https://van-tran-19.github.io/posts/docker-learning/

IaaS virtualizes physical hardware using VMs. Each VMs requires its own complete guest operating system, which can be large, slow to boot, and costly to scale. Containers bring solution to this problem by virtualizing the OS rather than the hardware. A container packages code and its dependencies into an isolated runtime environment on a shared host OS kernel. 

### Kubernetes

Kubernetes is an open-source platform for orchestrating and managing containerized applications across node clusters. At the highest level, Kubernetes is a set of APIs that can be used to deploy containers on a set of nodes called a cluster. Nodes are coputing instances (VMs or machines) that run the application containers. 

Kubernetes is composed by different layers. 

The smallest deployable unit which wraps one or more grouped containers is called Pod. It is responsible for sharing network IP, ports and storage volume accross its containers. 

<img width="718" height="718" alt="image 3" src="https://github.com/user-attachments/assets/ac04cd6d-726e-4026-9fb2-6a1eb92baafa" />


Then, the second component is called Deployment. It manages a group of identical Pod replicas. It ensures self-healing if nodes fail, handles scaling, and executes rolling updates. 

The last component is Service. It’s an abstraction defining a logical set of Pods and access policies. It provides a stable, fixed IP address to prevent connection issues when individual Pod IPs change. Automatically hooks into a Google Cloud Network Load Balancer in GKE for external access.

### Google Kubernetes engines (GKE)

GKE is a managed Kubernetes service hosted in google cloud. GKE offers the autopilot mode. Nodes, scaling, updates and security are fully managed by the mode. Moreover, autopilot is designed to be optimized for production with automated security and ressource allocation out of the box. The standard mode lets user design all this settings manually, interesting if workloads requiring deep custom node-level configuration. Running Kubernetes inside GKE gives access to google services like integrated load balancing, node pools, autoscaling and auto-repair, auto-upgrades, and observability.
